Answers to common questions about testing changes safely and managing multi-location agents using variants.

<AccordionGroup>
  <Accordion title="How do I test changes safely before going live?" icon="flask">
    Work in a [Release](/environments-and-versions/introduction), your own isolated copy of the agent branched off Live.

    1. **Create a Release** from Live, so you start from what is actually running.
    2. **Make your change.** It saves as you go.
    3. **Test it** with [simulation tests](/testing/simulation-tests), or talk to the agent over an in-app call or chat. Tests run on any Release or Branch.
    4. **Move it to Staging** if you need a real phone number and staging API connections. This step is optional.
    5. **Publish.** Your Release merges onto Live and becomes the newest version in Live's history.

    You can [compare versions](/environments-and-versions/diffs) before publishing, and [roll back](/environments-and-versions/introduction#roll-back-live) in one step if issues arise.
  </Accordion>
  <Accordion title="Do I have to go through Staging?" icon="arrow-right-arrow-left">
    No. A Release publishes straight to Live once you have tested it. Move it into Staging only when you want to test with a real phone number and staging API connections first. Only one Release can sit in Staging at a time.
  </Accordion>
  <Accordion title="Can I test on a Branch?" icon="code-branch">
    Yes. Tests run on any Release or Branch, before it merges anywhere.
  </Accordion>
  <Accordion title="Will publishing overwrite a colleague's work?" icon="shield-check">
    No. Publishing merges onto Live rather than replacing it. If Live has moved on since you created your Release, your Release is marked out of sync and you must sync and resolve any conflicts before you can publish.
  </Accordion>
  <Accordion title="What happens to my Branches if someone publishes the Release they came from?" icon="code-merge">
    Nothing is lost. Any Branch still open moves to sit directly under Live and becomes a Release in its own right. Carry on working, then publish it like any other Release.
  </Accordion>
  <Accordion title="How deep can workspaces nest?" icon="layer-group">
    Three layers: Live, Release, Branch.
  </Accordion>
  <Accordion title="Where does the app open?" icon="door-open">
    On the last thing you were working in, whether that is Live, a Release or a Branch.
  </Accordion>
  <Accordion title="How do I manage multi-site or multi-location agents?" icon="location-dot">
    Use [variant management](/knowledge/variants/introduction) to manage location-specific content in a single agent. Each variant stores attributes like phone numbers, addresses, and hours.

    Variants are useful for:
    - Hotel chains, restaurant groups, or retail chains with multiple branches
    - Agents that need to respond differently based on which number was called
    - Dynamically populating responses with location-specific data using `${variant_attribute}` syntax

    See the [variant management guide](/knowledge/variants/introduction) and [CSV imports](/knowledge/variants/csv-imports) for bulk configuration.
  </Accordion>
</AccordionGroup>
