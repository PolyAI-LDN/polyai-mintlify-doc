## Agents as code, in your repo

Every agent resource is a versioned file: YAML for settings, Python for functions. Pull a project, edit it in any IDE or with a coding assistant, validate, push. Branch, diff, review and roll back with the Git workflow you already run.

| Step | Command | What it does |
| --- | --- | --- |
| 01 | `poly init` | Load an existing project into a local folder, or start one with `poly project create`. |
| 02 | `poly pull` | Bring down the latest resources before you edit. |
| 03 | `poly validate` | Check your YAML and Python before anything leaves your machine. |
| 04 | `poly diff` · `poly push` | See exactly what changed, then push it. Safe to run from CI. |
| 05 | `poly chat` · `poly call` | Talk to the agent you just pushed, by text or on a real voice call. |

## Let your coding agent do the building

Two MCP servers, one account API key. **Builder MCP** lets Claude Code, Cursor or Codex build, test and publish agents in your project. **Data MCP** answers questions about your conversations, metrics and call outcomes. Both use streamable HTTP, and their endpoints follow the region you picked above.

<RegionCode
  title="Builder MCP in Claude Code"
  code={"claude mcp add --transport http polyai \\\n  {{host}}/builder-mcp \\\n  --header \"X-API-KEY: $POLYAI_API_KEY\" \\\n  --header \"Accept: application/json, text/event-stream\""}
/>

<RegionCode

## Dialog-RSN-1

Audio in, text out. Dialog-RSN-1 speaks the OpenAI Realtime event protocol over WebSocket, with `poly_*` extensions for knowledge, spoken tool fillers and playback reporting. Turn detection, recognition and the reply come from one model; speech synthesis is yours.

| | |
| --- | --- |
| **Modality** | Audio and text in, text out. A request for audio output is refused. |
| **Protocol** | OpenAI Realtime events over WebSocket, plus `poly_*` fields and `poly.output_audio.*` playback reports. |
| **Endpoint** | `wss://api.us.poly.ai/v1/realtime`, with `X-API-KEY` or `Authorization: Bearer`. Browsers can't set either header, so put a relay in front. |
| **Context** | 32,000 tokens across instructions, tools, knowledge, history and audio. Keep the static session setup under about 20k. |
| **Session** | One conversation per connection. No resumption, and nothing compacts history. |
| **Tools** | JSON Schema function tools, same shape as Realtime. MCP tool entries are dropped. |
| **Languages** | English for voice. |

```json session.update
{
  "type": "session.update",
  "session": {
    "type": "realtime",
    "output_modalities": ["text"],
    "instructions": "Collect the six-digit booking reference. Wait until the caller has said all six digits.",
    "audio": {
      "input": {
        "format": { "type": "audio/pcm", "rate": 16000 },
        "turn_detection": { "type": "server_vad" }
      }
    },
    "tools": [{
      "type": "function",
      "name": "lookup_booking",
      "parameters": {
        "type": "object",
        "properties": { "reference": { "type": "string" } },
        "required": ["reference"]
      }
    }]
  }
}
```

<Warning>
**Constraints worth knowing.** A refused `session.update` applies nothing, instructions included: `turn_detection: null`, turn timing fields, `semantic_vad`, `audio.output` and `reasoning` all get it refused. Always declare the PCM `rate`; 16 kHz audio sent without one is read as 24 kHz. Once a session has had audio, keep streaming it, silence included.
</Warning>
