![connect-flow](/images/integrations/amazon/connect-flow.png)

Use the [Amazon Connect integration](https://aws.amazon.com/marketplace/pp/prodview-rwoh2vu3mruba?sr=0-1&ref_=beagle&applicationId=AWSMPContessa) to connect PolyAI voice agents to your Amazon Connect instance. You set it up from a guided setup in Agent Studio, then run a PolyAI CloudFormation stack in your own AWS account.

## How the integration works

Amazon Connect transfers the call to a PolyAI number over the phone network (PSTN). PolyAI reads and updates the contact attributes through an IAM role in your AWS account.

![connect-diagram](/images/integrations/amazon/diagram.png)

1. **Claim a number**: your contact flow invokes the `PolyAIWriteContactAttributesToDDB` Lambda function. It claims a free number from the pool of PolyAI numbers you picked, and saves it as the `ExternalPolyNumber` contact attribute. Each call in progress gets its own number, because PolyAI matches each call to its contact by the number dialed.
2. **Transfer to PolyAI**: the flow transfers the call to that number. PolyAI reads the contact attributes, so the agent has the caller's context.
3. **Conversation**: the PolyAI agent greets the caller and runs its flows, such as identity verification or information collection.
4. **Hand back**: before hanging up, PolyAI sets the `should_transfer` contact attribute to `true` or `false`. The contact flow resumes and routes on it: to an agent queue, or to end the call.

<Note>
  Only one telephony integration can be connected to a project at a time. If the project already has another one connected, the Amazon Connect setup shows **Another telephony integration is connected** and does not start.
</Note>

## Before you start

- An active Amazon Connect instance, and access to the AWS console with permission to create a CloudFormation stack and IAM resources in that account.
- At least one PolyAI number in the project. If you don't have one, buy one first from **Add number** → **Buy Twilio number** in the **Telephony** tab.
- Enough numbers for your peak traffic. Each call that runs at the same time needs its own number.

## Set up Amazon Connect in Agent Studio

Go to **Integrations** → **Telephony** and click **Add number**. In the **Add a number** panel, under **Integrate with your contact center platform**, select **Amazon Connect**. The **Amazon Connect setup** opens.

<Note>
  If the Amazon Connect option shows **Coming soon**, contact your PolyAI account manager.
</Note>

<Steps>
  <Step title="Instance">
    Under **Your Amazon Connect instance**, fill in:

    - **Instance ARN**: in the AWS console, open Amazon Connect and copy the [ARN](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference-arns.html) of your instance. It looks like `arn:aws:connect:us-east-1:123456789012:instance/00000000-0000-0000-0000-000000000000`. Once the ARN is valid, the setup shows the region and AWS account it found. Both are used for the rest of the setup.
    - **PolyAI numbers Connect transfers to**: select the project numbers Connect can transfer calls to. Each option shows the number and its environment. Pick one number per call that can run at the same time. The PolyAI stack gives each call a free number from this pool, so two calls never share one. Select at least one.

    Click **Next**. PolyAI saves the connection and prepares a CloudFormation link for your account. From here you can't go back to change the instance.
  </Step>

  <Step title="AWS stack">
    Under **Run the PolyAI stack in AWS**, you create the IAM role that lets PolyAI read and update contact attributes on your instance. PolyAI can't see anything else in your account.

    1. Click **Open in AWS console**. CloudFormation opens in your AWS console with the template and every parameter already filled in.
    2. Tick the acknowledgement that the stack creates IAM resources, then create the stack.
    3. Wait for the stack to reach `CREATE_COMPLETE`. It usually takes under a minute.

    The step also shows copy buttons for the **Stack name** and **Template URL**, if you'd rather create the stack yourself.

    Back in Agent Studio:

    - **IAM role ARN** is prefilled from your instance. Change it only if you renamed the role when you created the stack.
    - Tick **The stack reached CREATE_COMPLETE**.

    Click **Finish setup**. You see **Amazon Connect setup submitted**.

    If the link doesn't load, you see **Couldn't build the AWS link**. Click **Try again**, or contact PolyAI support.
  </Step>

  <Step title="Reference">
    The last step shows what to build in your contact flow, the **PolyAI numbers Connect transfers to**, and the **Role ARN** and **External ID** PolyAI uses. See [Finish in Amazon Connect](#finish-in-amazon-connect).
  </Step>
</Steps>

If saving fails, you see **The setup did not save**. Click the button again to retry, or contact PolyAI support if it keeps failing.

### While PolyAI finishes the connection

After you finish setup, your side is done. PolyAI completes its own setup and lets you know when calls can flow, usually within one business day:

1. PolyAI grants itself access to the role you created, using the external ID.
2. PolyAI confirms the numbers are reachable from your instance.
3. You're told when the connection is live.

Until then:

- The **Telephony** tab shows **Amazon Connect setup is pending**. Click **View setup** to review what you submitted.
- **Amazon Connect** shows as **Pending** in the **Add a number** panel.
- If you closed the setup before ticking **The stack reached CREATE_COMPLETE**, opening it again takes you back to the **AWS stack** step.

You can build the contact flow while you wait.

## Finish in Amazon Connect

Build or update the contact flow that should send calls to PolyAI. First, [add the `PolyAIWriteContactAttributesToDDB` Lambda function to your instance](https://docs.aws.amazon.com/connect/latest/adminguide/connect-lambda-functions.html#add-lambda-function), so the flow can invoke it.

1. **Set the caller context.** Set any contact attributes the PolyAI agent needs.
2. **Invoke the Lambda function.** Add an **Invoke AWS Lambda function** block that calls `PolyAIWriteContactAttributesToDDB`. It claims a free PolyAI number for the call and saves it as the `ExternalPolyNumber` contact attribute. Don't hard-code a number.
3. **Transfer to PolyAI.** Add a **Transfer to phone number** block. Set the number dynamically from the `ExternalPolyNumber` contact attribute (namespace **User Defined**). Set **Resume flow after disconnect** to **Yes**. Without it, the flow ends at the transfer.
4. **Route on `should_transfer`.** After the transfer, branch on the `should_transfer` contact attribute:
   - `true` or empty: transfer to an agent.
   - `false`: end the call.

   The flow only resumes when PolyAI hangs up with the caller still on the line.
5. **Keep a fallback.** Leave `should_transfer` unset for a PolyAI fallback, so the call still reaches an agent.
6. **Assign a phone number.** Assign the Amazon Connect number your callers dial to the flow, then save and publish it.

![contact-flow-steps](/images/integrations/amazon/contact-flow-steps.png)

<Note>
  Make sure the contact flow handles failures, for example PolyAI being unreachable or the Lambda function failing to set `ExternalPolyNumber`. Route these cases to a fallback, such as a queue or an error message, rather than leaving the caller stuck.
</Note>

### Use an AI assistant for the Connect side

The **Reference** step shows **Have an AI assistant prepare the Connect side**. Click **Copy prompt** and paste it into an AI assistant that can work in your AWS console.

The prompt already includes your instance ARN, number pool, IAM role ARN and external ID. The assistant asks you which contact flow should send calls to PolyAI, which queue handed-off calls go to, and how many calls can run at once. It then builds the contact flow, asks before publishing a flow that takes live calls, and replies with a summary of what it configured.

## Test the integration

Once PolyAI tells you the connection is live:

1. Call the number assigned to your contact flow and check the PolyAI agent answers with the right context.
2. Trigger a handoff and check the call reaches the agent queue.
3. Place several calls at once and check each gets its own PolyAI number.
4. Use Amazon Connect analytics to track call volume, routing and handoffs.

## Chat and messaging handoff

For webchat and SMS conversations, PolyAI escalates to a live agent through the Amazon Connect [Chat API](https://docs.aws.amazon.com/connect/latest/APIReference/API_StartChatContact.html) instead of a call transfer. This is set up separately, under **Integrations > Amazon Connect** in Agent Studio. See [Amazon Connect chat handoff](/integrations/chat/amazon-connect) for the full guide.

| Field | Required | Description |
|-------|----------|-------------|
| `instance_id` | Yes | The Amazon Connect instance ID. |
| `contact_flow_id` | Yes | The contact flow that routes the chat to a queue. |
| `role_arn` | Yes | IAM role PolyAI assumes to call `StartChatContact`. |
| `aws_region` | No | Region of the Connect instance (for example, `eu-west-2`). Overrides the PolyAI worker's default region. |
| `api_url` | No | Override for the Connect API endpoint. |
| `headers` | No | Static headers to include on API calls. |

### When to set `aws_region`

PolyAI's messaging handoff worker uses a default AWS region. If your Amazon Connect instance is in a different region (for example, your worker defaults to `us-east-1` but your Connect instance lives in `eu-west-2`), set `aws_region` on the integration so `StartChatContact` targets the right region. Without this override, the handoff fails with a `ResourceNotFoundException`.

Use the [region code](https://docs.aws.amazon.com/general/latest/gr/connect_region.html) shown in the Amazon Connect console URL (for example, `eu-west-2`, `us-west-2`, `ap-southeast-2`).

```json
{
  "instance_id": "12345678-aaaa-bbbb-cccc-1234567890ab",
  "contact_flow_id": "abcdef12-3456-7890-abcd-ef1234567890",
  "role_arn": "arn:aws:iam::123456789012:role/PolyAIAccessConnect",
  "aws_region": "eu-west-2"
}
```

### IAM trust policy requirements

PolyAI's handoff worker runs on EKS with [IRSA](https://docs.aws.amazon.com/eks/latest/userguide/iam-roles-for-service-accounts.html), which adds session tags to its credentials when chain-assuming your IAM role. Your `PolyAIAccessConnect` role's trust policy must therefore allow both `sts:AssumeRole` **and** `sts:TagSession` from the PolyAI worker account. If `sts:TagSession` is missing, the assume-role step fails before any Connect API call is made.
