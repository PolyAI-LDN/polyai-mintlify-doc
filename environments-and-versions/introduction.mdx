Your agent has a **Live** version. That is the one your customers are talking to right now. You never edit Live directly. Instead you make your changes somewhere safe, test them, and then **publish**. Publishing is the moment your changes reach customers.

Every publish is saved as a version in Live's history. If a change goes wrong, you can **roll back** to any earlier version in one step.

## Publishing adds, it never overwrites

When you publish, your changes are **merged** onto Live. Merging means your changes are added on top of what is already there, rather than replacing it.

That matters when more than one person is working. If a colleague published something while you were still editing, their change is kept. If you both changed the same thing, you are asked which version to keep before anything goes live. Nothing is lost silently.

## Three ways to work

Agent Studio has three **deployment modes**. A mode sets how many people can work on changes at once, and how their changes are kept apart until they publish.

New projects start in **Simple mode**. To see which mode you are in, or to change it, open **Settings** on the Deployments page. Switching mode never deletes any work.

| **Mode** | **How it works** | **Best for** |
|---|---|---|
| [**Simple**](/environments-and-versions/simple-mode) | You make changes in a draft, test it, and publish. One draft, one publish at a time. | One person making straightforward changes. The default for new projects. |
| [**Branches**](/environments-and-versions/branches-mode) | Each person works in their own separate copy of the agent, called a Branch, and publishes it when ready. Nobody waits for anyone else. | Small teams working on separate changes at the same time. |
| [**Sub-branches**](/environments-and-versions/sub-branches-mode) | A team shares one Branch, splits the work into Sub-branches, and publishes everything together. | Several people building one update that ships as a package. |

<Frame caption="Choosing a deployment mode under Deployment settings">
  <img src="/images/deployment/deployment-settings-modes.png" alt="Deployment settings showing the Simple, Branches and Sub-branches options" style={{ maxWidth: '720px', width: '100%', margin: '0 auto', display: 'block' }} />

Each mode has its own page, written so you can read it on its own. Start with the mode you are in.

## Roll back a change

Rolling back works the same way in every mode.

<Steps>
  <Step title="Open Live history on the Deployments page">
    Every publish is listed there as a version.
  </Step>
  <Step title="Choose an earlier version and roll back">
    Live returns to that version in one step. Nothing else changes.
  </Step>
</Steps>

<Tip>
Because publishing merges rather than replaces, a rollback cannot be silently undone by someone else's publish.
</Tip>

## Terminology

| **Term** | **What it means** |
|---|---|
| [**Live**](/environments-and-versions/environments#live) | The version of your agent that customers are talking to. |
| **Publish** | Put your changes live. Every publish becomes a version in Live's history. |
| **Merge** | How publishing adds your changes on top of Live instead of replacing it. |
| **Roll back** | Put an earlier version of Live back. |
| [**Environment**](/environments-and-versions/environments) | A separate place your agent can run, so the version you are editing is never the one answering customers. |
| [**Sandbox**](/environments-and-versions/environments#sandbox) | The environment where you build and test. Nothing here reaches a customer. |
| [**Staging**](/environments-and-versions/staging) | An optional environment for testing a change the way a customer would experience it. Not available in Simple mode. |
| **Draft** | Your working copy in Simple mode. It saves as you go, and customers never see it until you publish. |
| [**Branch**](/environments-and-versions/branches-mode) | Your own separate copy of the agent, in Branches and Sub-branches modes. Publishing merges it onto Live. |
| [**Sub-branch**](/environments-and-versions/sub-branches-mode) | A copy made from a Branch rather than from Live, so a team can split one piece of work between them. It merges back into its Branch. |
| **Sync** | Pull in changes that others have published since you started, so your copy is up to date. |
| [**Out of sync**](/environments-and-versions/branches-mode#handle-an-out-of-sync-branch) | Live has changed since you started your copy. You need to sync before you can publish. |
