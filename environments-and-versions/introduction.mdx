Your agent has a **Live** version. This is the version your customers interact with. You never edit Live directly.

Instead you work in a copy of the agent, called a **Branch**. It saves as you go, without affecting the Live version. When you are ready to push the changes to customers, you **publish**. This creates a new Live version, and from that moment it handles every customer conversation.

## Publishing

When you publish, your changes are **merged** onto Live. Merging means your changes are added on top of what is already there, rather than replacing it.

That matters when more than one person is working on a project. If a colleague publishes their Branch while you are still working on yours, your change is added on top of theirs. If you both changed the same thing, you are asked which version to keep before anything goes live. Nothing is lost silently.

## Rolling back a change

Every publish is saved as a version in Live's history. If a change goes wrong, you can roll back to an earlier version in one step.

</Tip>

</Note>

## Two ways to work

Every project can have as many Branches as you need, and any Branch can be split into **Sub-branches**. You decide which to use for each piece of work, depending on whether the change ships on its own or as part of a larger update.

| | **How it works** | **Best for** |
|---|---|---|
| [**Branches**](/environments-and-versions/branches) | Each person has their own Branch and publishes it when ready. Nobody waits for anyone else. | One person making a change, or a small team working on separate changes at the same time. |
| [**Sub-branches**](/environments-and-versions/sub-branches) | A team shares one Branch, splits the work into Sub-branches, and publishes everything together. | Several people building one update that ships as a package. |

## Terminology

| **Term** | **What it means** |
|---|---|
| [**Environment**](/environments-and-versions/environments) | Where your agent runs. Your project has more than one, so the version you are editing is never the one customers are using. |
| [**Live**](/environments-and-versions/environments#live) | The environment that runs the version of your agent your customers talk to. |
| [**Sandbox**](/environments-and-versions/environments#sandbox) | The environment where you build and test. Nothing here reaches a customer. |
| [**Staging**](/environments-and-versions/environments#staging) | An optional environment for testing a change the way a customer would experience it. |
| [**Branch**](/environments-and-versions/branches#what-a-branch-is) | A copy of the agent that you make your changes in. Usually each person has their own, or a team shares one and splits it into Sub-branches. Publishing merges it onto Live. |
| [**Sub-branch**](/environments-and-versions/sub-branches#what-a-sub-branch-is) | A copy made from a Branch, so a team can split one piece of work between them. It merges back into its Branch. |
| [**Publish**](#publishing) | Push your Branch to Live. Your changes are merged onto Live, and every publish becomes a version in Live's history. |
| [**Merge**](#publishing) | Join two copies of the agent into one. Your changes are layered on top of what is already there, so nothing is replaced. A Branch merges onto Live, and a Sub-branch merges into its Branch. |
| [**Roll back**](#rolling-back-a-change) | Put an earlier version of Live back. |
| [**Sync**](/environments-and-versions/branches#handling-an-out-of-sync-branch) | Pull in changes made to the parent since you started, so your copy is up to date. A Branch's parent is Live. A Sub-branch's parent is its Branch. |
| [**Out of sync**](/environments-and-versions/branches#handling-an-out-of-sync-branch) | The parent has changed since you started. You need to sync before you can merge or publish. |
