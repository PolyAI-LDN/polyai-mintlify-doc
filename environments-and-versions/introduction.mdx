Every project has a **Live** version, the agent actually talking to your customers. You never edit Live directly. Instead you make your changes in an isolated copy of your agent and publish them onto Live when ready. Each publish creates a new version in Live's history, and you can roll Live back to any previous version.

## Terminology

| **Term** | **Description** |
|---|---|
| **Live** | The environment serving your customers. You never edit it directly. Publishing merges changes onto it, and each publish creates a new version in its history. You can roll back to any previous Live version. |
| **Branch** | An isolated copy of your agent, branched off Live. Publishing merges it back onto Live. |
| **Sub-branch** | An isolated copy of your agent, branched from a Branch. It only ever merges back into its parent Branch. |
| **Sandbox** | The environment where you build and test. It has no telephony or API connections, so nothing you build here can reach a real system. |
| **Staging** | An optional environment where you can test with a real phone number and API connections, one Branch at a time. |
| **Out of sync** | Your working copy is behind its parent. Pull the parent's changes in before publishing or merging. |

## Deployment modes

Choose how you want to manage changes under **Deployment settings**, and change mode as your team grows.

| **Mode** | **How it works** | **Best for** |
|---|---|---|
| [**Simple**](/environments-and-versions/simple-mode) | No Branches. You edit your agent's working copy, which is automatically in Staging, and publish it onto Live when ready. | A single builder making straightforward changes. |
| [**Branches**](/environments-and-versions/branches-mode) | Branches off Live, each publishing onto Live on its own. No Sub-branches. | Small teams working in parallel, each publishing their own isolated changes. |
| [**Sub-branches**](/environments-and-versions/sub-branches-mode) | The full model: Branches off Live, split further into Sub-branches. | Several people building updates that ship as one package. |

Every mode keeps the same foundations: publishing merges onto Live, each publish creates a version in Live's history, and you can roll Live back to any previous version. A lighter mode simply removes layers. Switching to a lighter mode never deletes existing work; it only stops you creating the layer it removes.

  <Step title="Open Live's version history">

  </Step>
  <Step title="Select a previous version and roll back">
    Live returns to that version in one step.
  </Step>
</Steps>

<Tip>
Because publishing merges rather than replaces, a rollback cannot be silently undone by someone else's publish.
</Tip>
