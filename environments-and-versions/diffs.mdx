Use comparison before publishing changes to catch unintended edits. A diff shows exactly what changed between any two branches or Live versions, across knowledge, functions, flows, variants, and settings, so you can publish with confidence.


## When to use it

- **Before publishing a Branch onto Live:** review all changes to confirm nothing unexpected is included.
- **After a model upgrade:** verify that no unintended changes were introduced alongside the upgrade.
- **When you find a Branch you didn't expect:** understand what's in it, who made the changes, and whether to keep or discard it.
- **In shared Branches:** when multiple people work in Sub-branches of the same Branch, use the diff to verify a teammate's changes before merging or publishing. For example, if a customer needs a quick fix while your team is building in a separate Branch, compare branches to confirm the fix is isolated.

## Key features

- **Side-by-side comparison** across Live, Branches and Sub-branches
- **Full platform coverage:** diffs apply to knowledge, functions, flows, variants, and settings
- **Change attribution:** each change shows who made it and when, which is useful for compliance, regulated industries, and multi-team projects
- **Content diff** for responses, sample questions, and configuration

## How it works

1. **Select what to compare:** Choose two branches from the dropdown menu. You can compare a Branch against Live, a Sub-branch against its parent Branch, or two versions in Live's history.
2. **Review differences:** Changes are highlighted in a structured format:
   - **<Icon icon="plus" iconType="solid" color="#2D8C66" /> Additions** – a new item was added.
   - **<Icon icon="minus" iconType="solid" color="#D64F4F" /> Deletions** – an existing item was removed.
   - **<Icon icon="rotate" iconType="solid" color="#3B73D1" /> Edits** – an existing item was modified.
3. **Check attribution:** Each change is annotated with the user who made it. Use this to audit who changed what, which is especially useful when multiple people have access to the same project.
4. **Assess impact:** Use the comparison view to evaluate whether changes are ready to publish.
5. **Exit comparison mode:** Return to the editor or switch to another branch for further review.

## Using diffs with branching

The diff tool is most valuable in collaborative and branching workflows. A common pattern:

1. A customer or teammate needs to make a quick change to the live agent.
2. They create a Branch from the current Live version and make the change there.
3. Before publishing, they use **Compare branches** to confirm only the intended change is present – nothing from an in-progress build is included.
4. They publish, and the isolated change merges onto Live.

This workflow keeps in-progress work separate from urgent fixes. The diff tool is how you verify the separation.
