Staging is an optional environment where you test one Branch through real channels before you publish it to Live.

Most testing does not need it. Your Branch lives in Sandbox, where you can talk to your agent over an in-app call or chat. API and app connections can be configured for Sandbox as well, so your integrations work there too.

What Sandbox cannot give you is a real channel. Someone calls a number, sends a text, emails an address or messages a widget. The platform has to know which version of your agent should answer. A shared environment cannot answer that, so a channel connects to one Branch only. This is why Staging holds a single Branch.

## When to use Staging

Use Staging when you need to test through a channel a customer would actually use:

- Call a phone number and hear your agent answer.
- Use the widget as a visitor would on your website.
- Receive an SMS on a phone.
- Receive an email in a real inbox.
- Give a colleague a number to call, without publishing to Live.

## Connections and credentials

Connections are configured per environment, and Staging uses the ones set up for Staging. A test through Staging reaches whatever those connections point at.

Most teams configure Staging with different credentials from Live, so that testing does not affect production systems. To confirm what a test will reach, check the connections configured for Staging in your project.

### Set up Staging connections

Each connection needs pointing at Staging separately. Channels, meaning phone numbers and widgets, exist in Staging and Live only. APIs, apps and functions are also configured for Sandbox, where every Branch shares them.

- **Phone numbers.** Numbers are grouped by environment under **Voice > Numbers**. Assign one to Staging. This requires a telephony integration between your provider and PolyAI first. See [Phone numbers](/voice-channel/numbers/route-management).
- **Apps.** Pre-built integrations live under **Integrations > Apps**, each with a guided setup. You connect an account and choose which environment its credentials apply to, so Staging can use a test account while Live uses production. The exact steps differ for each app. See [Integrations](/integrations/introduction).
- **APIs you set up yourself.** Add the API under **Integrations > APIs**. Each environment gets its own base URL and authorisation, and PolyAI stores the credentials for you. Point Staging at your test services and Live at production. See [APIs](/integrations/api/introduction).
- **Widgets.** A widget targets one environment, chosen under **Integrations > Widgets**. Set it to Staging to test the widget against your Branch. You can move a widget between environments without re-embedding it. See [Configure a widget](/widgets/configure).
- **Custom functions.** Store each credential in the [Secrets Vault](/secrets/how-to-setup). Your function then selects the right one for the environment it is running in, using `conv.env`. See [Environment configuration](/tools/variables#environment-configuration).

<Warning>
API authentication is set per environment, not per branch. Changing it on one branch changes it for every branch in that environment.
</Warning>

<Note>
MCP servers, under **Integrations > MCP**, are not configured per environment. An agent connects to the same MCP server in Staging as it does on Live.
</Note>

## Move a Branch to Staging

<Steps>
  <Step title="Open the Deployments page">
    Find your Branch in the list.
  </Step>
  <Step title="Move it to Staging">
    Use the Branch's actions menu.
  </Step>
  <Step title="Call the Staging number">
    Your agent answers from that Branch, using the connections configured for Staging.
  </Step>
  <Step title="Publish when you are ready">
    Publishing works the same as it does from Sandbox. Your Branch merges onto Live.
  </Step>
</Steps>

<Note>
Each project has one Staging environment, holding one Branch at a time. Moving another Branch to Staging replaces the one already there, so agree with your team who is using Staging before you move yours. Support for multiple Staging environments is coming soon.
</Note>

## Edit a Branch in Staging

You cannot edit a Branch directly while it is in Staging. How you change it depends on your mode.

- **In [Branches mode](/environments-and-versions/branches-mode)**, move the Branch out of Staging, make your change, then move it back.
- **In [Sub-branches mode](/environments-and-versions/sub-branches-mode)**, make your edit in a Sub-branch and merge that Sub-branch into the Branch.

Either route makes the update to Staging deliberate. Your changes save as you go, so without this a Branch would change while someone was testing on it. If you have given the Staging number to a colleague, they keep a stable, tested version until you choose to update it.
