Staging is an optional environment where you test one Branch on a phone number, with API connections, before you publish it to Live.

Sandbox has no telephony or API connections, so nothing you build there reaches an external system. Staging covers the tests Sandbox cannot run.

## When to use Staging

Most changes go straight from Sandbox to Live. Use Staging when you want to:

- Hear your agent on a phone number before your customers do.
- Check that your agent works correctly against your connected systems.
- Give a colleague a number to call, without publishing to Live.

## Connections and credentials

Staging uses the telephony and API connections configured for the Staging environment. A call to Staging reaches whatever those connections point at.

Most teams configure Staging with different credentials from Live, so that testing does not affect production systems. To confirm what a test call will reach, check the connections configured for Staging in your project.

### Set up Staging connections

Connections are configured per environment, so each one needs pointing at Staging separately.

- **Phone numbers.** Numbers are grouped by environment under **Voice > Numbers**. Assign one to Staging. This requires a telephony integration between your provider and PolyAI first. See [Phone numbers](/voice-channel/numbers/route-management).
- **Apps.** One-click and guided integrations, such as your CRM or booking system, are set up from **Integrations**, on the page for that integration. See [Integrations](/integrations/introduction).
- **APIs you set up yourself.** Add the API from **Integrations**. Each environment, Draft, Staging and Live, gets its own base URL and authorisation, and PolyAI stores the credentials for you. Point Staging at your test services and Live at production. See [APIs](/integrations/api/introduction).
- **Widgets.** A widget targets one environment, chosen in the widget editor. Set it to Staging to test the widget against your Branch. You can move a widget between environments without re-embedding it. See [Configure a widget](/widgets/configure).
- **Custom functions.** Store each credential in the [Secrets Vault](/secrets/how-to-setup). Your function then selects the right one for the environment it is running in, using `conv.env`. See [Environment configuration](/tools/variables#environment-configuration).

<Warning>
API authentication is set per environment, not per branch. Changing it on one branch changes it for every branch in that environment.
</Warning>

<Note>
MCP servers are not configured per environment. An agent connects to the same MCP server in Staging as it does on Live.
</Note>

## Move a Branch to Staging

<Steps>
  <Step title="Open the Deployments page">
    Find your Branch in the list.
  </Step>
  <Step title="Move it to Staging">
    Use the Branch's actions menu.
  </Step>
  <Step title="Call the Staging number">
    Your agent answers from that Branch, using the connections configured for Staging.
  </Step>
  <Step title="Publish when you are ready">
    Publishing works the same as it does from Sandbox. Your Branch merges onto Live.
  </Step>
</Steps>

<Note>
Each project has one Staging environment, holding one Branch at a time. Moving another Branch to Staging replaces the one already there, so agree with your team who is using Staging before you move yours. Support for multiple Staging environments is coming soon.
</Note>

## Edit a Branch in Staging

You cannot edit a Branch directly while it is in Staging. How you change it depends on your mode.

- **In [Branches mode](/environments-and-versions/branches-mode)**, move the Branch out of Staging, make your change, then move it back.
- **In [Sub-branches mode](/environments-and-versions/sub-branches-mode)**, make your edit in a Sub-branch and merge that Sub-branch into the Branch.

Either route makes the update to Staging deliberate. Your changes save as you go, so without this a Branch would change while someone was testing on it. If you have given the Staging number to a colleague, they keep a stable, tested version until you choose to update it.
