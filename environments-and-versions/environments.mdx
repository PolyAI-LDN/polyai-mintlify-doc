Every project has three environments. You build in Sandbox, optionally test on your channels in Staging, and serve customers from Live.

## Sandbox

Sandbox is where you build. Every Branch and Sub-branch lives here, as does your working copy in [Simple mode](/environments-and-versions/simple-mode).

You test in Sandbox by running [simulation tests](/testing/simulation-tests), or by talking to your agent over an in-app call or chat. Your API and app connections work here, using the credentials set up for Sandbox, so your integrations behave as configured. Every Branch shares those connections.

Sandbox has no channel connections. A channel connection points at one version of your agent, and Sandbox holds every Branch at once. There would be no way to tell which should answer. Staging and Live each run a single version, so that is where channel connections live.

## Staging

Staging is optional, and it holds one Branch at a time. That is what lets it have its own channel connections, so you can reach a Branch the way a customer would.

It also has its own integration credentials, so most teams point Staging at test accounts and services rather than production ones. See [Staging](/environments-and-versions/staging) for how to set it up and move a Branch into it.

## Live

Live is the version serving your customers. You never edit it directly.

Publishing merges your changes onto Live and creates a new version in its history. If something goes wrong, you can roll Live back to any previous version in one step.

## What each environment gives you

| | **Sandbox** | **Staging** | **Live** |
|---|---|---|---|
| **What it is for** | Building and testing in the app | Testing on a channel | Serving customers |
| **Branches** | Every Branch and Sub-branch | One at a time | The published version |
| **Channel connections** | None | Its own | Your production ones |
| **Integrations** | Shared by every Branch | Its own credentials | Your production credentials |
| **Who reaches it** | You and your team, in the app | Anyone you give the details to | Your customers |

## What else is set per environment

Beyond channels and integrations, several settings hold a separate value in each environment. Changing one in Sandbox does not change it in Live.

- **Real-time configuration.** Values and schemas are set per environment, and changes take effect immediately rather than waiting for a publish. See [Real-time configuration](/real-time-config/introduction).
- **Knowledge topic activation.** A topic can be active in one environment and inactive in another, so you can test a change before customers see it. See [FAQs](/knowledge/faqs/introduction).
- **Connected sources.** Each source is enabled per environment. See [Sources](/knowledge/sources/introduction).

Functions can also behave differently per environment by reading `conv.env`. See [Environment configuration](/tools/variables#environment-configuration).
